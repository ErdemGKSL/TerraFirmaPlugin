# M0-BM-01: BetterModel carrier and lifecycle
**Status:** partial — 2026-10-16. Verified on Paper 1.21.11 only, with a Cow carrier. Horse, Folia, 26.3, chunk reload and the walk clip are not verified. See Open.

- Models: `tools/models` generator (`species/tfp_example_bovine.json`, 14 bones, 64x64) plus TFC `Deer-Bedrock.bbmodel` converted with `tfc_anim/convert.py` (kept `walk`/`run`). `spikes/bm-01/tools/prep-models.sh` runs both, then `spikes/bm-01/tools/fill_box_uv.py` (see Findings 1). Models registered from the jar via `ModelAssetsEvent`.
- Server: Paper 1.21.11-132 (`c5eb079`), BetterModel 3.5.1, CraftEngine 26.9.2, PacketEvents 2.14.0, Java 25. Port 25900 (RCON 25910). Run dir `/tmp/claude-0/bm01-m0-1.21.11`. Started with `client/server.sh paper 1.21.11 <dir> 25900 bm-01.jar`.
- CE: `self-host.ip: "127.0.0.1"`. Packs rebuilt with `ce reload all` (see Findings 3).
- Client: vanilla 1.21.11 headless client on display :102, GUI scale 2 (`client/mcclient.py`). Bot in creative. The carrier is at (0.5,100,0.5) on a grass platform at y=99, with `forceload` on chunks -2..2.

## Findings (the important ones)
1. **Generator writes zero face UVs, so BetterModel renders the model invisible.** `tools/models/tfpmodels/bbmodel.py` line 92 writes `uv: [0,0,0,0]` for every face of `box_uv` cubes. Blockbench recomputes them on load, but BetterModel reads the stored values and draws nothing. TFC's `Deer-Bedrock.bbmodel` has real face UVs (138/138 non-zero). The spike works around this in `spikes/bm-01/tools/fill_box_uv.py`. The layout matches Blockbench's own output for TFC's Deer and Bear models (120/120 faces). The generator still needs the fix; it is a shared change and was not made here.
2. **Carriers loaded before the models register get no tracker.** On restart, `EntitiesLoadEvent` runs first. The bovine stays invisible until something calls `getOrCreate`. Fix: re-attach carriers in `PluginEndReloadEvent` (done in the spike, idempotent). The BetterModel skill already says this; it is now verified.
3. **CraftEngine's first pack build can miss BetterModel content.** On a fresh run dir, the first `generated/resource_pack.zip` had no `bettermodel` entries. One `ce reload all` after the BetterModel reload fixed it (25 tfp entries, then 13 bovine items). Same pattern as BetterHud in M0-BH-01.
4. **Model scale is read from the SCALE attribute** unless the scaler says otherwise. `ModelScaler.entity()` alone does not shrink a baby (Finding in the table above).
5. **Test-harness traps**, not product issues: (a) a dead bot's `playerdata/*.dat_old` makes every rejoin dead; (b) `fill` does nothing for unloaded chunks ("not loaded"), so the test platform needs `forceload`. The BM-01 runs used both fixes.

## Decision / recommendation
- Carrier model: a Cow carrier is viable on Paper 1.21.11 for walk pathfinding, eat override, baby scale, and tint persistence through PDC re-apply (`CreateEntityTrackerEvent`). PDC re-apply is required: it is the only way tint survives `/bm reload` and restart.
- Baby size: use `ModelScaler.entity().multiply(0.5f)` (or a scaler from age) rather than relying on the SCALE attribute. Either explicit approach works; the attribute path also changes vanilla baby size for the carrier, which we may not want.
- After startup or restart, re-attach carriers in `PluginEndReloadEvent`. Do not rely on `EntitiesLoadEvent`.
- Model generator: fix `bbmodel.py` to write real per-face box-UV rectangles (or export via Blockbench). Do not ship zero-UV models.
