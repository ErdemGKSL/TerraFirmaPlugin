## Findings (the important ones)
1. **Generator writes zero face UVs, so BetterModel renders the model invisible.** `tools/models/tfpmodels/bbmodel.py` line 92 writes `uv: [0,0,0,0]` for every face of `box_uv` cubes. Blockbench recomputes them on load, but BetterModel reads the stored values and draws nothing. TFC's `Deer-Bedrock.bbmodel` has real face UVs (138/138 non-zero). The spike works around this in `spikes/bm-01/tools/fill_box_uv.py`. The layout matches Blockbench's own output for TFC's Deer and Bear models (120/120 faces). The generator still needs the fix; it is a shared change and was not made here.
2. **Carriers loaded before the models register get no tracker.** On restart, `EntitiesLoadEvent` runs first. The bovine stays invisible until something calls `getOrCreate`. Fix: re-attach carriers in `PluginEndReloadEvent` (done in the spike, idempotent). The BetterModel skill already says this; it is now verified.
3. **CraftEngine's first pack build can miss BetterModel content.** On a fresh run dir, the first `generated/resource_pack.zip` had no `bettermodel` entries. One `ce reload all` after the BetterModel reload fixed it (25 tfp entries, then 13 bovine items). Same pattern as BetterHud in M0-BH-01.
4. **Model scale is read from the SCALE attribute** unless the scaler says otherwise. `ModelScaler.entity()` alone does not shrink a baby (Finding in the table above).
5. **Test-harness traps**, not product issues: (a) a dead bot's `playerdata/*.dat_old` makes every rejoin dead; (b) `fill` does nothing for unloaded chunks ("not loaded"), so the test platform needs `forceload`. The BM-01 runs used both fixes.

## Decision / recommendation
- Carrier model: a Cow carrier is viable on Paper 1.21.11 for walk pathfinding, eat override, baby scale, and tint persistence through PDC re-apply (`CreateEntityTrackerEvent`). PDC re-apply is required: it is the only way tint survives `/bm reload` and restart.
- Baby size: use `ModelScaler.entity().multiply(0.5f)` (or a scaler from age) rather than relying on the SCALE attribute. Either explicit approach works; the attribute path also changes vanilla baby size for the carrier, which we may not want.
- After startup or restart, re-attach carriers in `PluginEndReloadEvent`. Do not rely on `EntitiesLoadEvent`.
- Model generator: fix `bbmodel.py` to write real per-face box-UV rectangles (or export via Blockbench). Do not ship zero-UV models.

### New findings
1. **Folia: carrier lookup by last location misses wandering carriers.** `bm01 status` reported "not found within 32 blocks" when the Cow had wandered into another region. `onCarrier` in `spikes/bm-01` only searches the region of its last known location. This is a spike-code bug: production code does not do it, because the BetterModel adapter finds trackers by carrier UUID and callers hold entity references. Do not copy the spike lookup.
2. **`moveTo` returns false right after `NoAI` is cleared.** A 1 s wait fixed it. It also returned false when the target was on the platform's edge. Not a BetterModel bug, but a test-harness trap.
3. **Folia RCON:** `data get/merge entity <uuid>` fails ("Unknown or incomplete command") on 1.21.11 and 26.3; `tp <uuid>` works. `fill` output goes to the server log, not the RCON reply.
4. **Spawn before the platform exists** lets the carrier fall to natural terrain (Folia 26.3 Cow ended at y=69). Build the platform first.
5. **Texture colour changes with facing.** The bovine texture is a multi-colour placeholder (blue, red, tan, green, grey blocks). Apparent colour changes between shots were the Cow turning, not a bug.
6. **PacketEvents** logs "Failed to parse packetevents version" (GitHub API 403 through the proxy) on Folia. Not a bm01 issue.

### New findings (session 3)
1. **Carriers can come back with AI disabled.** At the start of this session the cow and the horse carried `NoAI:1b`. The cow's `moveTo` returned `ok=true` and the cow did not move until `data merge entity <uuid> {NoAI:0b}`. The spike code never calls `setAI`/`setAware` (grep), and the BetterModel 3.5.1 jar has no `setAI` call. The origin is UNVERIFIED. Production walk code must check displacement, not `moveTo`'s return value, and must clear AI if it finds it off.
2. **Teleporting a rider dismounts it (vanilla).** A rider does not stay mounted across a 2000-block teleport. Re-mounting after the horse reloads works and keeps the same seat offset. Code that moves riders must re-mount them.
3. **Spike logging gaps.** For the horse on Paper and the cow on Folia, the unload/load events were not logged this session (`EntitiesUnloadEvent`/`EntitiesLoadEvent` absent), even though the chunk did unload and reload. `/bm01 status` also skipped the horse after the reload (no line, no "not found"). The last-location lookup in `Bm01Plugin.onCarrier` is the likely cause. Do not copy it.
4. **RCON traps.** On Folia, `data get entity <player>` and `data get/merge entity <uuid>` are not usable; use `tp <uuid>` to move carriers. `execute if entity @e[...]` run from the console on Folia throws "Cannot getEntities asynchronously". Harness-side, not a plugin bug.
5. **Test-state changes made in this session** (run dirs only): cow and horse `NoAI` was cleared/set for the tests; cow tint is red, `horn_r` hidden in the Folia world; `forceload` on chunk (0,0) was removed in both worlds (the Paper world's platform chunk is no longer forced).
