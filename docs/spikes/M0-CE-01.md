# M0-CE-01: CraftEngine blocks from our ChunkGenerator

**Status:** done (2026-10-16), all 4 targets.

## Setup
- `spikes/ce-01/`: a flat Bukkit `ChunkGenerator` (default world via `bukkit.yml`, plugin `load: STARTUP`) that writes CE `BlockData` resolved once from `CraftEngineBlocks.getBukkitBlockData(state)`:
  - noise stage (`ChunkData.setBlock`): `tfpspike:marker` (no block entity) and `tfpspike:marker_be` (our `BlockBehavior` + `BlockEntityController`, records the constructing thread);
  - `BlockPopulator` (`LimitedRegion.setBlockData`): a marker in its own chunk **and** one in the east neighbour chunk.
- Check (region thread, per chunk): `CraftEngineBlocks.getCustomBlockState(block)` ("live") **and** CE's storage view `BukkitAdaptor.adapt(world).storageWorld().getBlockStateAtIfLoaded(...)`, plus `getBlockEntityAtIfLoaded(pos, false)`. Spawn area 7×7 chunks and a far 5×5 ring (generated, unloaded, waited 70 s past CE's cache TTL, reloaded).
- Phases per target (`spikes/ce-01/run.sh`): A default config (`delay-configuration-load: true`), B fresh world with `delay=false`, C restart, D fresh world with `cache-system: false`, E restart.

## Results
Identical on Paper 1.21.11, Paper 26.3, Folia 1.21.11, Folia 26.3:

| Phase | noise marker | noise BE marker | populator own | populator → neighbour chunk | BE record |
|---|---|---|---|---|---|
| A delay=true | CUSTOM 74/74 | CUSTOM 74/74 | CUSTOM | CUSTOM 62/62 | ok |
| B delay=false, generate | CUSTOM | CUSTOM | CUSTOM | CUSTOM | ok |
| B after unload + 70 s + reload | CUSTOM | CUSTOM | CUSTOM | CUSTOM | ok, `onLoad` count +1 |
| C restart | CUSTOM | CUSTOM | CUSTOM | CUSTOM | ok, data kept |
| D `cache-system: false`, generate | **LIVE_ONLY** | **LIVE_ONLY** | **LIVE_ONLY** | **LIVE_ONLY** | **missing** |
| E restart (cache false) | LIVE_ONLY | LIVE_ONLY | LIVE_ONLY | LIVE_ONLY | missing |

CUSTOM = live block and CE storage both report the marker. LIVE_ONLY = the server block is CE's `custom_N` state, but CE's storage doesn't know it (no behaviour, no block entity, no CE save).

- `LimitedRegion.getBuffer()` = 16 on all targets; every neighbour write was inside the region.
- Threads:
  - `generateNoise`/`populate` run on `Paper Common Worker` (Paper and Folia);
  - BE controllers are **constructed on the worldgen worker**;
  - `onLoad` runs on `Server thread` (Paper) / `Folia Region Scheduler Thread`;
  - `saveCustomData` runs on worldgen workers (end of generation) and on the region thread (unload/save).
- Phase A: with `delay-configuration-load: true` our markers weren't resolvable in `onEnable` (`CraftEngineBlocks.byId` → null until the first `CraftEngineReloadEvent`). No chunk was generated before that event on any target, because 1.21.9+/26.x don't pregenerate spawn chunks. So nothing was lost here. Any chunk generated in that window would get no CE blocks (the generator has no states yet).
- 26.3 servers default `white-list=true` (relevant for test harnesses, not for players).

## Decision
- **Writing CE `BlockData` from a Bukkit `ChunkGenerator`/`BlockPopulator` works and persists**, including cross-chunk populator writes. M2-GEN-07 can write cached CE states directly.
- **`chunk-system.cache-system: true` is mandatory.** With `false`, CE does not track worldgen-written blocks at all (worse than the expected "neighbour writes lost"). The installer must enforce it (M1-INST-02) and the self-test must check it.
- Keep `delay-configuration-load: false` as decided. The generator must refuse to run, with a clear error, if CE states aren't resolved yet, instead of silently writing vanilla stone.
- Controllers really are constructed on worldgen threads. That confirms the skill's rule: no world access in constructors/`loadCustomData`, use volatile/immutable fields.

## Open / UNVERIFIED
- `/ce reload` during generation (plan step 7) was not run. Production guidance stays "restart, don't reload".
- Chunky-style mass pregeneration was not measured here (see M2-GEN-15).
