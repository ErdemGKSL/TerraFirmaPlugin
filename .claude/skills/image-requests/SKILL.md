# Requesting images (Claude side)

Division of labour:
- **Claude** finds out what's needed and writes precise requests in `IMAGES.md`. Later, Claude reviews the generated files and wires them into the content (CraftEngine images/items, BetterHud assets, ...).
- **Codex/ChatGPT** generates the images (`AGENTS.md`, `/generate-required-images`) and post-processes them with `tools/images/postprocess.py`.
- **A human** approves them.

Claude doesn't generate art (no hand-written pixel arrays, no drawn SVG-to-PNG textures). Scripted placeholders for development are the one exception, see below.

## 1. Check before requesting
1. **TFC already has it?** Search the pinned TFC checkout: `assets/tfc/textures/{block,item,gui,entity,...}`. TFC covers almost every block/item/GUI. Prefer copying through datagen (`tfc-asset-migration`).
2. **Derivable from an existing texture?** Recolours, overlays, crops and composites are deterministic transforms. Do them in `tools/datagen` (Pillow) rather than requesting new art.
3. **Already requested?** Search `IMAGES.md` for the same target path or purpose. Update the existing entry instead of adding a duplicate.

Request art only for plugin-specific needs that TFC never had: the outside-inventory button, HUD frames that BetterHud layouts need, the pack icon, GUI screens that exist only in our plugin, and ledger divergences that need a new visual.

## 2. Write the entry
Append it under `## Requests` in `IMAGES.md`, following the template there. A good entry lets the generator succeed on the first try:
- **id:** kebab-case, unique, prefixed by area (`ui-`, `hud-`, `tex-`, `item-`, `pack-`).
- **Target path:** under `content/art/...`, matching where datagen/our installers pick it up.
- **Size:** exact pixels, plus grid/frame layout for sheets (e.g. `48x24, two 24x24 cells: normal | hovered`). For GUI backgrounds, give slot coordinates if slots must align (vanilla slot = 18×18 including border, item area 16×16).
- **Used by:** which system consumes it (CE `images:` glyph for a container title, BetterHud listener image with `split: 25`, item model texture, ...), so the generator knows the constraints.
- **Description:** what it depicts, states/frames, light direction (TFC: top-left).
- **References:** concrete TFC texture paths to match palette/style. Always give at least one.
- **Constraints:** transparency, alpha translucency allowed or not, tiling, animation frame count, "no text", palette size.
- **Requested by:** feature/skill + date.
- Status: `requested`.

Also add a `TODO(image:<id>)` comment at the place in code/config that will consume the image, so wiring it later is easy to find.

## 3. Placeholders while waiting
To keep features testable, datagen may emit a **placeholder**: a flat-colour PNG at the exact size with a 1-px magenta border, generated by script, never committed under the final target path's name. Use `content/art/_placeholder/<id>.png` and point the config there until the real image is `approved`. The visual checklist flags any placeholder still in use.

## 4. When images come back
For each entry with status `generated`:
- Verify the file: exact size, RGBA, alpha 0/255 unless allowed, no text, palette consistent with the references. Look at it with the Read tool.
- Wire it in (replace the placeholder reference), then run the relevant showcase/visual checklist (`plugin-testing`).
- Record the outcome in the entry's `Notes`. Approval (`approved`) is the human's call. You may recommend it, or set `rejected` with a concrete reason and a corrected spec, which returns it to `requested`.
