# M0-BH-01: BetterHud integration
**Status:** done — 2026-10-16

## Setup
- Plugin: `spikes/bh-01` (`Bh01Plugin`, throwaway). Placeholders `tfp_health` (45), `tfp_max_health` (50), `tfp_thirst` (1 Hz counter, 100 down to 0 and back) and listener `tfp_thirst` (0..1), read from an immutable per-player snapshot (`ConcurrentHashMap<UUID, Snapshot>`). The snapshot is written every 20 ticks on the player's entity/region scheduler. Placeholders and listeners only read the map.
- Content: `spikes/bh-01/pack/betterhud/` copied by `setup_run.py` into `plugins/BetterHud/packs/tfp/` (one `tfp_main` HUD, layout `tfp_vitals` at gui {50,100}: health and thirst bars with text `[tfp_health]//[tfp_max_health]` and `Thirst [tfp_thirst]`). `default-hud` is set to `[]` so the demo HUD does not show.
- Vanilla hiding: 56 transparent sprites (`gui/sprites/hud/heart/*`, `food_*`, `air*`) in the CE resource folder `plugins/CraftEngine/resources/tfphud/`. The set was checked to be identical in the 1.21.11 and 26.3 client jars.
- Servers: Paper 1.21.11-132 (`c5eb079`), Paper 26.3-196 (`7ec11b2`), Folia 1.21.11-14 (`529aabc`), Folia 26.3-3 (`597e413`), Java 25. CraftEngine 26.9.x (`mwFiNxVO`), BetterHud 2.2.0-SNAPSHOT-449 (dev build, logs warn "be careful"), PacketEvents 2.14.0.
- Commands: `./gradlew -q :bh-01:jar`, then `bash spikes/bh-01/run.sh prepare <paper|folia> <mc>` and `bash spikes/bh-01/run.sh shots <mc> <scales...>`. Port 25700 (RCON 25710), display :101. Folia checks were done by hand (join, creative teleport, survival, screenshot, log scan) with the same RCON port.
- Clients: vanilla 1.21.11 and 26.3 headless clients (`client/mcclient.py`), GUI scales 1-4, 1280x720.

### Problems found on the way (and what they mean)
1. **HUD missing on clients after the first start.** CE built and uploaded its pack at startup while BetterHud was still reloading (`[BetterHud] BetterHud is still on reload!`). BetterHud merged into CE's output 5 s later, but the uploaded zip had 0 `assets/betterhud/` entries, so the client showed tofu boxes instead of text and no bars. A second `ce reload all` (after `Successfully merged with CraftEngine`) put 1488 BetterHud entries into `CraftEngine/generated/resource_pack.zip`, and the HUD appeared. Found on Paper 1.21.11 and 26.3 and reproduced on both Folia servers before the retry loop was added.
2. **Test harness faults, not product faults.** The bot drowned once in survival while spawning in water. Its saved player data then kept health 0, and every later join showed "You Died!". Paper also falls back to `playerdata/<uuid>.dat_old` when `.dat` is missing, so deleting only `.dat` did not help. Fixed in `run.sh` by teleporting in creative first and deleting both files before each client launch.
3. **Unloaded test platform.** `fill` silently fails with "That position is not loaded" on 26.3 without a player nearby, so the bot fell to y=51. `forceload add -16 -16 16 16` before the fills fixed it. The position log line shows the bot at (-2.31, 151, -2.31) on the platform for all final land shots.

## Decision / recommendation
- BetterHud can be the HUD carrier on Paper and Folia, 1.21.11 and 26.3. Values come from snapshot placeholders, the `tfp_thirst` listener works, and the HUD updates about once per second. Vanilla hearts/food/air can be hidden with transparent sprites in the CE pack. The hotbar is kept.
- **Production rule:** after BetterHud's startup reload, rebuild the CE pack, and do it again after any change to the HUD files. `dependency-bootstrap` should wait for BetterHud's merge (or call `ce reload all` once after `Successfully merged`) before the first pack build. A single CE build at startup is not enough.
- Keep the placeholder functions O(1) and snapshot-only, as in the spike. Nothing here touched Bukkit world or entity state from BetterHud threads.

- Not measured: HUD update cost (MSPT), memory, and behaviour across `/hud reload` or a BetterHud upgrade.
- The `betterhud` skill says BetterHud reloads on every CE build. This spike shows that BetterHud's merge can land after CE's upload at startup. The skill was not edited (spike rules). The main session should add this to the skill and to `dependency-bootstrap`.
